## Why

The Assessment Command Center and Coordinated Entry screens shipped in `assessments-and-coordinated-entry` (archived `2026-09-24`) run on deliberate placeholders: a fixed-weight `ScoringService` tally instead of a real housing-stability/VI-SPDAT-style engine, no stage-eligibility rules (any HUD stage can be recorded at any time, with no draft/resume/annual-window logic), and a Coordinated Entry question set that doesn't exist as configurable data. Case managers can't yet resume an in-progress assessment, can't see why a score came out the way it did, and Coordinated Entry recommendations/overrides are not driven by anything an admin could change without a code deploy. This change replaces both placeholders with real, configurable models and completes the case detail page's Assessments tab, which `case-workspace` intentionally left as a toast-only stub pending this work.

## What Changes

- Add HUD stage-eligibility logic (`AssessmentEligibilityService`) governing when an Entry/Update/Annual/Exit assessment may be started on a program enrollment, including the ±30-day annual window, one-Entry/one-Exit limits, and draft-forces-resume behavior.
- Add a real, configurable `HousingStabilityScoringService` backed by a `scoring_rules` table (seeded with a clearly marked provisional rule set) and an `assessment_score_contributions` audit trail, replacing the fixed-weight placeholder tally. **BREAKING**: `Assessment.score`/`scoreLabel` are now computed by this engine and are no longer simple placeholder values — any code or test asserting the old placeholder tally's output must be updated.
- Add `program_exits` recording, wired so completing an Exit assessment closes the program enrollment (sets end date/status) in the same transaction.
- Add care-plan-template recommendations driven by a new `care_plan_template_rules` table (score band or field condition → template), replacing the "every published template, no real signal" placeholder from `case-workspace`.
- Add a Launch Assessment flow (client → enrollment → allowed stage) and a full Assessment form modal (carry-forward, reused intake section components, disabilities editor, Exit Details) to the Assessment Command Center, plus Resume/Discard actions for drafts.
- Complete the Case detail page's Assessments tab with the same form/detail components, replacing its current placeholder toast.
- Replace the Coordinated Entry placeholder scoring with a configurable rule model: `ce_questions`/`ce_answer_options` (client-facing question bank), `ce_score_bands` (score → priority + recommended project types), `ce_flag_overrides` (Veteran/Unaccompanied Youth/Safety Alert add/replace behavior, including referral suppression), and an audit trail (`ce_rule_changes`). **BREAKING**: the existing `VulnerabilityAssessment.answers` free-form JSON bag is superseded by structured `ce_assessments`/`ce_responses` rows tied to the question bank — new vulnerability assessments no longer write the old shape.
- Add a `CoordinatedEntryService` engine (score → band → base recommendation, override application, suppression) and wire the existing 4-step Coordinated Entry wizard and Prioritization List to it, including live bed-availability lookups for recommended partner programs.
- Add a rule-admin API (`ce:manage-rules` permission-gated CRUD for questions/answer options/score bands/flag overrides, each writing an audit row) — API and permission check only; the editor UI is out of scope for this change (a later Admin Panel phase).
- **BREAKING**: the Prioritization List's five quick filters move from independently-toggleable/AND-composable to single-select (one active filter at a time), matching this change's `GET /api/ce/priority-queue?filter=...` contract — combining two quick filters is no longer possible.

## Capabilities

### New Capabilities
_(none — this change extends existing capabilities rather than introducing new ones)_

### Modified Capabilities
- `assessment-tracking`: adds stage-eligibility rules, draft/resume/discard lifecycle, the real scoring engine with persisted contributions, carry-forward, disabilities editing, Exit Details/program-exit recording, and care-plan-template recommendations. Replaces the placeholder scoring requirement from the prior change.
- `coordinated-entry`: adds the configurable question/answer/score-band/flag-override rule model and audit trail, replacing the fixed placeholder scoring requirement; adds the rule-admin API surface and permission gate; adds live bed-availability to recommended programs.
- `case-management`: the Case detail page's Assessments tab moves from a placeholder (toast-only Resume/New) to a fully functional tab reusing the new assessment form/detail components, including "Create from Template" on recommended care plans.

## Impact

- **Database**: extends `assessments` — `status`/`due_date`/`score`/`scoreLabel`/`type` already exist and are reused unchanged; only `assessor_id`, `legacy_sync_status`, and `legacy_sync_date` are new columns. `disabilities` and `referrals` need no schema changes (reused as-is). `beds`/bed-assignment tables are reused read-only for availability. `care_plan_templates` gains a new `care_plan_template_rules` condition table. `program_enrollments` gains `end_date`. `programs` gains `project_type_code`/`operating_organization_id` (needed for Coordinated Entry's project-type → partner-program matching). New tables: `program_exits`, `assessment_score_contributions`, `scoring_rules`, `care_plan_template_rules`, `ce_questions`, `ce_answer_options`, `ce_score_bands`, `ce_flag_overrides`, `ce_rule_changes`, `ce_assessments`, `ce_responses`. `VulnerabilityAssessment` is dropped, superseded by `ce_assessments`/`ce_responses`.
- **Backend**: new `AssessmentEligibilityService`, `HousingStabilityScoringService`, `CoordinatedEntryService`; new/extended routes under `/api/assessments`, `/api/enrollments/:id/*`, `/api/ce/*`; a new `User.role` column plus a `requirePermission` middleware backing the `ce:manage-rules` check; the placeholder `scoring.service.ts` is deleted, not extended.
- **Frontend**: extends `apps/web/src/features/assessments/` (Launch Assessment modal, Assessment form modal, richer detail page) and `apps/web/src/features/coordinatedEntry/` (question-driven Vulnerability Assessment modal, recommendation/override display, suppression banner); extends `apps/web/src/features/cases/panels/AssessmentsPanel.tsx` to a real tab. Reuses (does not duplicate) the living-situation/income-benefits/health-DV/disabilities section components built for the `client-intake` wizard's steps 4-6, and any confirm-dialog/stepper/modal primitives already in `apps/web/src/components/ui/`.
- **Dependencies**: builds on `client-intake` (3b — assessment draft model, disclosure-field pattern, HUD situation code map), `case-workspace` (4b — Case tab structure, beds/BedAssignment, care plan templates, Benefit/BenefitAssignment), and `assessment-tracking`/`coordinated-entry` (5 — the placeholders this change replaces).
